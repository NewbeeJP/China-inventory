# 中国库存系统 — 设计文档

日期：2026-08-11

## 背景

目前用一张 Excel（`中国库存用.xlsx`，单个 sheet「20260722库存」，442 行 × 59 列）由 3-4 个人共同维护中国仓库的进销存台账。每次有新一批货的入库/出库/订单，就在表格右侧新增几列记录，导致表格越来越宽、列头难以对齐。文件靠传来传去协作，经常出现版本冲突、覆盖别人修改的问题。

现有表格的核心信息：
- 每行是一个商品：品名（中/罗马字）、材质（中文/日文两种写法）、品番(SKU)、装箱数、CTN箱数、净重/毛重、长宽高、CBM、日元单价、人民币单价等
- 每一批货（按海运批次，如"商事海运""慧光海运"，带装柜/到港日期）用几列记录该批次下各商品的入库/出库/订单数量
- 业务含义：
  - **入库**：工厂把货送到中国仓库，仓库收货
  - **出库**：仓库把货装船发往日本
  - **订单**：给工厂下的生产订单，可能还未生产/入库，仅作为在途/预期库存参考，**不影响库存数字**
  - 实时库存 = 期初库存 + 累计入库 − 累计出库

最左侧原有一列"编号"是运输时给箱子编的编号，与商品无关，新系统不保留。

## 目标

把这张 Excel 迁移为一个网页版进销存系统，满足：
- 有网络就能打开，多人（3-4人）同时使用不再有版本冲突
- 电脑端录入数据为主，手机端主要用于随时查看库存和流水
- 保留 Excel 那种"一眼看到很多信息"的高密度表格体验，而不是简化成逐条点开的卡片式界面
- 全部免费或接近免费

## 技术架构

**前端直连 Supabase，无自建后端**（相当于本次讨论的方案A）：

- **数据库/鉴权/实时同步**：Supabase（Postgres 数据库 + 内置账号登录 + Realtime 推送）
- **前端**：React + Vite + TypeScript 单页应用，部署在 **Cloudflare Pages**（静态托管，免费额度无限制）
- 前端通过 `supabase-js` 直接读写数据库，权限用 Supabase 的 Row Level Security 控制（已登录用户可读写，不做公开访问）
- 登录方式：Supabase 邮箱/密码登录，为 4 个人各建一个账号，不开放注册
- **多人协作不再冲突的原理**：不再有"文件"概念，所有人打开的是同一个网页、同一个数据库；每一笔出入库是"新增一行流水"而不是"覆盖同一个单元格"，天然不会互相覆盖；同时启用 Supabase Realtime，一个人录入后，其他人屏幕上的库存和列表会自动更新，不需要手动刷新

放弃的方案：
- 中间加一层 Cloudflare Worker 做自建后端 API —— 对当前"把 Excel 搬上网、大家一起用"的需求是过度设计，以后真需要复杂业务逻辑（比如自动锁单）再加也不迟
- 用 Retool 等低代码后台工具套壳 —— 界面通用模板感强，做不出贴近 Excel 高密度体验的列表，且免费额度有限

角色权限：本期不做精细化角色区分，4 个账号权限一致，都能编辑所有字段（当前实际工作方式就是如此）。

## 数据模型

### `products`（商品资料）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 自增整数 | 系统自动生成的编号，新增商品自动往下排 |
| name_cn | text，必填 | 品名（中文） |
| name_en | text，可空 | 罗马字/英文名 |
| material_cn | text，可空 | 材质（中文） |
| material_jp | text，可空 | 材質（日文） |
| sku | text，可空，不强制唯一 | 品番，就是原表那一列，允许为空 |
| box_qty | numeric，可空 | 数/箱 |
| ctn | numeric，可空 | CTN箱数 |
| net_weight / gross_weight | numeric，可空 | 净重/毛重 (kg) |
| length / width / height | numeric，可空 | 长/宽/高 (cm) |
| cbm | numeric，可空 | 材积 |
| price_jpy | numeric，可空 | 日元单价 |
| price_rmb | numeric，可空 | 人民币单价 |
| reorder_point | numeric，可空 | 库存预警线，实时库存低于此值时列表标红 |
| opening_stock | numeric，默认 0 | 期初库存（数据迁移那一刻的库存快照，作为起点） |
| photo_url | text，可空 | 商品图片地址（本期不做上传功能，字段先预留） |
| created_at / updated_at | timestamp | 自动记录 |

### `exchange_rate`（汇率设置，单行表）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 固定为 1 | 单行表，全局只有一条记录 |
| rmb_to_jpy | numeric，必填 | 当前汇率：1 人民币 = 多少日元 |
| updated_by / updated_at | 外键 / timestamp | 自动记录谁、什么时候改的 |

在商品资料的"价格"区域实时展示当前汇率，并提供入口手动编辑（4 个账号都能改，改了立即对所有人生效，配合 Realtime 自动刷新）。

### `transactions`（出入库流水）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 自增整数 | |
| product_id | 外键 → products.id，必填 | |
| type | enum：`inbound`(入库) / `outbound`(出库) / `order`(订单)，必填 | |
| quantity | numeric，必填 | 数量 |
| date | date，必填 | 发生日期，默认今天 |
| note | text，可空 | 备注，自由填写（例如"商事海运 3/16装柜"），不强制结构化批次 |
| created_by | 外键 → 用户 | 自动记录录入人 |
| created_at | timestamp | 自动记录，即操作日志 |

**实时库存计算**：`实时库存 = products.opening_stock + SUM(inbound) − SUM(outbound)`，按需查询计算，不做冗余存储字段，避免同步不一致。`order`(订单) 类型不参与库存计算，只在流水里展示为"在途/在产"参考信息。

## 数据迁移范围

- ✅ 导入：商品资料（品名/规格/材质/品番/箱规/单价等）+ 当前实时库存数量（写入 `opening_stock`）
- ❌ 不导入：442 行历史里每一笔入库/出库/订单流水明细
- 旧 Excel 文件保留存档，需要查历史批次记录时回旧文件查

## 页面与功能

1. **登录**：Supabase 邮箱密码登录，4 个账号，不开放注册
2. **商品列表（首页）**：
   - 密集表格视图，一屏尽量展示多列（编号、品名、品番、材质、数/箱、CBM、日元单价、人民币单价、实时库存、最近动向）
   - 顶部：搜索框（品名/品番）+「仅看预警」筛选按钮 + 「新增商品」按钮
   - 实时库存低于 `reorder_point` 的行整行标红
   - 点击整行进入商品详情页
   - 移动端：横向滚动查看，或收窄为关键列 + 展开查看更多
3. **商品详情页**：
   - 资料卡（品名、品番、材质、规格、价格等），可编辑，编辑用与"新增商品"相同的表单
   - 登记出入库/订单的轻量表单：类型（入库/出库/订单，三选一）+ 数量 + 日期（默认今天） + 备注，一键提交
   - 该商品自己的历史流水时间线：日期、类型（出库红/入库绿/订单灰徽章区分）、数量、备注、操作人
4. **新增/编辑商品表单**：分组字段（基本信息、材质、包装参数、价格、库存设置），只有品名必填，其余可先留空后补；新增时额外有「期初库存」「预警线」
   - 价格区域显示当前汇率（如"当前汇率 1 RMB = 36.3 JPY"，带编辑入口），日元单价 / 人民币单价两个输入框：改动其中一个，另一个按当前汇率实时算出来并自动填入；两个字段本身仍然是各自独立存储、都可再手动微调覆盖（比如凑整数）
   - 汇率只在当时录入/编辑那一刻用于换算，之后单独修改全局汇率**不会**倒回去改已保存商品的单价，避免历史价格被意外改动
5. **全部流水页**：
   - 汇总所有商品的入库/出库/订单记录，按时间倒序
   - 筛选：商品搜索、类型、日期区间
   - 表格列：日期、品名、品番、类型、数量、备注、操作人
   - 顶部「登记一笔」按钮，可选择任意商品直接登记
6. **导出**：商品列表页和全部流水页各有「导出 Excel」按钮；商品列表导出当前库存快照，流水页导出所选筛选条件下的明细

## 错误处理

- 出库导致库存变负数时，弹出确认提示（不强制拦截——先出库后补入库记录是正常业务场景），提醒"数量是否填错"
- 表单必填项（品名 / 数量+类型+日期）做前端校验，未填不能提交
- 断网时手机端展示上一次缓存的数据，不白屏；重新连网后自动刷新

## 测试

- 核心场景手动验证：新增商品 → 登记入库 → 登记出库 → 库存预警行标红 → 全部流水页能筛出对应记录 → 导出 Excel 内容正确
- 多人并发场景验证：两个账号同时给同一商品登记出入库，库存数字最终一致，互不覆盖
- 移动端浏览器（Safari/Chrome）验证列表/详情页可正常查看

## 本期不做（后续可加）

- 商品图片上传（字段已预留）
- 精细化角色权限（比如只读账号）
- 对接外部汇率 API 自动获取实时市场汇率（本期用手动维护的固定汇率）
- 历史流水明细的批量导入
